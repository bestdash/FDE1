The problem

A tool nobody uses renews itself for another year.

An invented but typical case: the contract renews automatically unless we say no 90 days before the end. Nobody looked in time, so we pay a full year more for something we wanted to stop.

~120 ha year spent in review calls to catch the next deadlines

Reading it

Same searches, same bytes, same tokens: the one MCP run that got the same pages as the tool (16,260 bytes, 3 calls) cost 22,873 tokens against 22,775. The MCP median is higher because its searches returned different, longer pages.

On the one-search question (Vendor07), whole pages made the model search less (2 calls instead of 3), so tokens stayed flat: 4,996 against 5,344.

Real contracts are longer, but the search cuts each section at 1,000 characters and returns at most 8. A big contract adds sections, not bigger results. Whole pages are the uncapped case.

How the cents are estimated: tokens are measured as a total, so I price them at Claude Sonnet 5.5 rates ($2 per million tokens in, $10 out), assuming about 700 tokens of answer (two answers measured on Nov 6: 419 and 764). Today = the expected 5 questions a day; 10x = 50 a day; 22 working days. Three more ways were ruled out early: a skill, a subagent, a description of an existing web API (section 02).

The architecture decision

I chose B: MCP for questions, with the same search kept inside the app

1. It meets the sponsor's need

He wants to ask in Claude Desktop, not in one more app. Option A cannot do that.

2. It costs almost nothing extra

Measured: the same tokens as A when the AI makes the same searches. The price is about 1 second per question, and one small program to deploy and look after.

3. C is not worth it yet

At most a few dollars a month to save, against building a sandbox and getting it through a security review.

What decides the bill

Not the way in. How many searches the AI makes, and how big each result is: 2 ¢ per question with short results, 5 ¢ with whole pages.

What would make me switch:
to C, when negotiation support needs more than 5 searches per question; away from MCP, if the company stops using Claude.

06 Decision

Step 6: decision, what I rejected, why, what would change my mind

Keep both doors to the same search. Code Mode waits for negotiation support.

Decision

MCP for questions, because the sponsor wants to ask through Claude Desktop, a client outside the app. The tool inside the app stays for the app's own loop: alerts and email replies, and the demo page. Both measured. Gap: owners without a Claude licence get alerts by email but cannot ask free questions yet.

What I rejected

Code Mode, in detail: it keeps search results out of the model's context, but runs model-written code, so it needs a sandbox (no keys, no network, a time limit). Not worth building: the whole bill is about $6 a month today and $56 at 10x volume, so it can save less than that.

The others in one line: UTCP (no contract API at work), a skill (the rules change slower than the code), a subagent (it would still read everything, so total tokens do not drop).

Why

Ordering question 2 is yes: a named outside client. MCP measured at the same tokens as the tool at equal searches, plus about 1 s. Parallel tool calls: 2 in the first reply, 12 of 12 runs. Limits: whole pages are a stand-in for real contracts; why MCP searched more on Vendor04 is not verified.

What would change my mind

Code Mode: when negotiation support starts (this year's and last year's contract, the quotes, public prices for similar tools), at more than 5 searches per request (today's maximum: 5), with a sandbox that has no network and a separate step that fetches public data.

Drop MCP: if the company stops using Claude, unless the assistant it moves to also speaks MCP.

07 What MCP does not carry

Claude Desktop gets the tools, not my instructions

Through MCP, Claude Desktop receives the tools and their descriptions. It does not receive the app's instructions to the model (cite every source in brackets, invent nothing, the rule before saying "missing"). So I asked the same questions in Claude Desktop three times. One run each, Nov 6.

What travels

No false "missing" in any round: the list_documents description ("Use it before saying a document is missing") reaches every client, because it is part of the tool.

What does not

The citation format lives only in the app's instructions. Without them, answers were richer (comparisons, negotiation advice) but less scoped and less traceable.

A rule that must hold for every client goes into the tool, not into the instructions.

One run per round, and rounds 2 and 3 returned fewer answers than asked (4 and 5 of 6). Round 1 used a stronger model, so round 3 repeats it on the endpoint's model. The other-vendor fix (a vendor filter in the search) is planned for Week 6 for this reason.

Still open, and what is next

Production waits for one approval. The alert is where the owner sees the value.

Stop tracking renewal dates in a spreadsheet. Stop writing vendor questions himself and only check the draft. Copy the shared contracts mailbox so the agent learns from real threads. Rely less on other people for routine renewal steps.

09 Bring it to work

Step 8: which capability at work, and what I would swap

The contract search, wrapped in an MCP server for Claude Desktop

Where at work: the contract search (search_chunks, list_documents) that the contract agent wraps in an MCP server, so contract owners can ask about IT contracts from Claude Desktop instead of a separate app. Step 8 pattern: a capability wrapped in an MCP server for one outside caller, Claude Desktop.

Data: one search returns 2,544 bytes with sections and 16,260 bytes with whole pages (the stand-in for real, longer contracts). The several-searches question needs 3 capability calls on the tool path (measured).

Model or endpoint: no contract API exists at work; the search is my code on a temporary VM. The model is the Anthropic API under the existing company agreement (chosen Nov 10). IT holds the API credential, dedicated to the contract agent; no credential on laptops.

Access or approval: IT to set up API credits for the agent and a way to watch cost; a deployment target for the MCP server that Claude Desktop can reach (local over VPN, or a remote endpoint with TLS and company login), to settle with IT security; later, a sandbox for Code Mode if cost needs cutting.
